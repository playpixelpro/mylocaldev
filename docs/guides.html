Guides

Recipes for the awkward cases

Short, task-focused walkthroughs. Each one assumes the app is already installed.

01 — Migration

Bring in a project you already have

Adding an existing folder should change as little as possible. MyLocalDev reads what is already there before it writes anything.

Add the folder

Choose the project root — the directory that contains composer.json, package.json or public/index.php.

Confirm the stack

The wizard pre-selects what it detected. Adjust the PHP version if the project targets an older one.

Keep your environment

Values already present in .env — including the app key and database name — are kept instead of being replaced.

# after importing, verify the project still sees its own settings
php artisan about
php artisan config:clear
02 — Versions

Run two PHP versions at the same time

Each project stores its own version, so nothing needs toggling when you switch folders.

# in the legacy project folder
php -v   → PHP 7.4.x

# in the new project folder
php -v   → PHP 8.5.x

# both web servers can be up simultaneously
https://legacy.test   → 7.4
https://rewrite.test  → 8.5

Install both builds from Binaries first. The PHP version dropdown on a project only lists what is installed.

03 — Node

Put a Node app behind Nginx or Apache

Use the project type Node.js and give it a start command. MyLocalDev proxies the .test host to the dev server, so the frontend behaves like a real site — cookies and all.

# typical project settings
Start command   npm run dev
Port            5173
Domain          app.test

If the dev server binds to 127.0.0.1 only, keep the proxy target on localhost. Binding to 0.0.0.0 is only needed for LAN access.

04 — Data

Move a database without leaving the app

Exports are plain dumps, so the result works anywhere — another project, another engine, another machine.

# export from the Databases screen, then:
mysql -u root -p shop < shop-2026-11-01.sql

# or restore gzipped dumps the same way
gunzip < shop.sql.gz | mysql -u root -p shop

Import progress is tracked in the UI, and a failed import reports the first statement that broke.

05 — Sharing

Send a working preview for an hour

Enable sharing on a single project. A tunnel is created for that host, and local URLs are rewritten so links and cookies keep working for whoever opens it.

# what the recipient gets
https://random-words.trycloudflare.com

Turn the toggle off when the review is done. Tunnels are for previews, not for hosting.

06 — Deployment

Prepare a project for a Windows server

Switch the project to Production mode before you copy it. The generated configuration becomes stricter and the runtime gets faster.

  • Environment values are forced to production and debug output is disabled.
  • OPcache and JIT are enabled; output buffering is tuned.
  • Queue workers start with retry limits and crash backoff.
  • A scheduled task can run schedule:run every minute without a console window.
# verify the production configuration on the server
php artisan about
php artisan schedule:list
07 — Maintenance

Update a runtime without losing settings

In-place updates keep custom ini directives, PHP extensions, CA certificates and global npm packages. Services and workers holding file locks are stopped first, then restarted.

# after an update, confirm the version the project sees
php -v
node -v
npm -v
08 — Troubleshooting

When something does not behave

Symptom Usual cause Fix
.test domain unreachable Hosts entry missing or browser cache Re-apply the domain from the project screen, restart the browser
502 from the web server PHP-CGI is not running for that project Stop and start the project; check the project log
Port already in use Another server owns 80 or 443 Let MyLocalDev reassign the port, or stop the other server
Certificate warning Local CA not trusted Trust the certificate authority again from settings
Database refuses the login Credentials changed after the project was created Update the stored database user/password, then re-save the project environment
Runtimes not detected Folder moved or antivirus quarantine Re-scan from Binaries; reinstall the affected version

Something still stuck?

Open an issue with the project log attached — it usually contains the answer already.
