Runtimes

Supported versions, without the guesswork

Download only what a project needs. Everything else stays off your disk.

Languages

PHP, Node.js and Python

Each version is a separate install with its own extensions, ini file and global packages.

Runtime Versions Notes
PHP 7.4 · 8.0 · 8.1 · 8.2 · 8.3 · 8.4 · 8.5 Extensions and php.ini editable per version; OPcache and JIT available in production mode
Node.js 16 · 18 · 20 · 22 · 24 Each version ships npm and npx; global packages survive runtime updates
Python 3.10 · 3.11 · 3.12 · 3.13 Useful for tooling and background scripts attached to a project
SQLite 3 Embedded engine — no port, no daemon
Web servers

Nginx, Apache, or both

The first server started claims 80 and 443; the other is proxied behind it automatically.

Server Versions Default ports
Nginx 1.24 · 1.26 · 1.28 80 / 443
Apache 2.4 80 / 443 when it owns the front door, otherwise 8081 / 8444

Tooling

Composer and Git

Both are managed like any other runtime: install once, use it from the built-in terminal and from project commands.

◧

Composer

Installed next to your PHP builds so dependencies resolve against the version the project actually uses.

  • Works from the GUI and the CLI
  • Can be imported manually as a phar
  • Updates independently of PHP
⑂

Git

Clone a repository straight into a project, with SSH keys generated and managed locally.

  • HTTPS and SSH remotes
  • Public key copied in one click
  • Uses your system Git when present
How ports stay predictable

Versions of the same engine are offset from its base port — MySQL 8.4 on 3306, 8.0 on 3307, 5.7 on 3308 — so two projects can talk to different builds at the same time. Every project screen shows the exact port in use.

Only install what you actually use

The default is an empty machine. Add a runtime the first time a project asks for it.
