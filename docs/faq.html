For classic PHP and Node projects, usually yes — without images, volumes or a daemon. Runtimes run directly on Windows, each in its own folder, which makes file watching, Xdebug and breakpoints noticeably simpler. If your project depends on Linux-only services, containers are still the better fit.

That is the primary use case. Point the wizard at an existing folder and it detects the framework and runtime. Your files are not rewritten: the environment file is read, not regenerated, and the values already in it — including the application key and database name — are preserved.

No manual edits. The app adds the required hosts entries (which is why it asks for administrator rights once) and generates the virtual host. Removing a project removes its entry again.

Projects, databases, certificates and logs live under one application-data folder in your user profile; downloaded runtimes live in a separate resource folder. Both paths are shown in Settings. Backing up means copying those two folders — nothing is hidden in the registry.

Yes. Different PHP, Node and web server versions can be active simultaneously because each project is pinned to its own build. Versions of the same database engine are offset onto different ports, so two projects can use different MySQL builds at once.

The wizard knows Laravel, Symfony, WordPress and plain PHP folders, plus Node.js projects such as Express, Next.js and Nuxt. Anything else works as a generic project: choose the runtime, document root and start command yourself.

It is a hardening preset, not a hosting platform. It enables OPcache and JIT, sets stricter headers, raises worker counts and prepares queue workers and a scheduled task — useful when a Windows machine actually serves the app. For internet-facing deployments, put a reverse proxy and proper monitoring in front.

The app checks the release feed and offers new versions. Runtime updates are separate: they replace files in place while keeping your ini directives, PHP extensions, certificates and global npm packages.

Yes. MyLocalDev is released under the MIT licence — free to use, modify and redistribute, with the licence text kept in the repository. Runtimes you download keep their own vendor licences.

There is no account and no analytics. The app contacts GitHub only to check for releases and to fetch runtime metadata; everything else stays on your machine.

The uninstaller removes the application. Project folders, databases and downloaded runtimes are left alone unless you explicitly clear them from the app's settings, so reinstalling picks up where you left off.

Two operations need elevation: writing to the hosts file and trusting the local certificate authority. Both can be skipped — you lose the friendly domains or the trusted HTTPS, nothing else.
